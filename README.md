# Rocky Production Scripts

This repository contains Bash tools for working with Prism Central and
provisioning a Rocky Linux 9 virtual machine as an XRDP workstation.

## Repository contents

| File | Purpose |
| --- | --- |
| `prism-central-inventory.sh` | Lists Prism Central clusters, images, storage containers, and subnets. Displays the results and writes a TSV inventory with names, ExtIDs, and cluster associations. |
| `create-rocky9-xrdp-vm.sh` | Resolves resource names from the TSV, creates and starts a VM, waits for cloud-init and SSH, then launches the remote workstation setup. |
| `cloud-config-tpl.yaml` | Cloud-init template used by the VM creation script to create the VM users, install SSH prerequisites, and configure SSH access. |
| `whichvapi.sh` | Tests VMM API versions `v4.0` through `v4.3` against the Prism Central images endpoint. |

## Requirements

- Bash, `curl`, and `jq`.
- For VM creation: `base64`, `ssh`, and `uuidgen`, plus Prism Central access.
- A Rocky Linux 9 image with cloud-init support.
- SSH public-key files for both VM users and the private key for the second
  user's key. Relative key paths are resolved from this repository directory.
- An inventory TSV generated by `prism-central-inventory.sh`.

The VM creation script reads `cloud-config-tpl.yaml` from the same directory.
The template's `{{USERID1}}`, `{{USERID2}}`, `{{USERID1PW}}`,
`{{USERID2PW}}`, `{{USERID1SSHKEY}}`, and `{{USERID2SSHKEY}}` placeholders are
filled from the script's command-line options. The second account is configured
with passwordless `sudo` for VM administration.

## Getting started

Make the scripts executable if needed:

```bash
chmod +x prism-central-inventory.sh create-rocky9-xrdp-vm.sh whichvapi.sh
```

### Generate a Prism Central inventory

The Prism Central password is requested interactively:

```bash
./prism-central-inventory.sh \
  --host 10.55.8.7 \
  --port 9440 \
  --username admin \
  --output PC-inv.tsv
```

Use `--insecure` only if you intentionally want to skip TLS certificate
verification. By default, certificate verification is enabled.

### Create a Rocky Linux VM

Choose resource names that appear in `PC-inv.tsv`. The Prism Central password
is requested interactively.

```bash
./create-rocky9-xrdp-vm.sh \
  --pc-host 10.55.8.7 \
  --pc-port 9440 \
  --pc-username admin \
  --prism-api-version 4.3 \
  --inventory-tsv-file PC-inv.tsv \
  --cluster-name "Cluster A" \
  --image-name "Rocky Linux 9" \
  --storage-container-name default \
  --subnet-name primary \
  --userid1 rocky \
  --userid2 rockyadmin \
  --userid1-pw 'REPLACE_WITH_PASSWORD' \
  --userid2-pw 'REPLACE_WITH_PASSWORD' \
  --userid1-sshkey-file id_ed25519.pub \
  --userid2-sshkey-file id_ed25519.pub \
  --ssh-private-key-file id_ed25519 \
  --vm-disk-size-gb 100 \
  --vm-memory-size-gb 24 \
  --vm-vcpus 4
```

The API version defaults to `4.3`. Run
`./create-rocky9-xrdp-vm.sh --help` for all options and defaults. The script
starts setup asynchronously; the VM reboots once and continues setup after
startup. Follow setup progress on the VM with:

```bash
sudo tail -f /var/log/rocky-xrdp-setup.log
```

VM account passwords are command-line arguments and may be visible in shell
history or process listings. Replace the example values and handle them
accordingly. Avoid committing passwords or private keys to this repository.
Use `--insecure` only when you intentionally want to skip Prism Central TLS
certificate verification.

### Check Prism Central VMM API versions

Before running `whichvapi.sh`, edit the `PC` and `PC_USER` values near the top
of the script. It prompts for the password and tests API versions `v4.0` through
`v4.3`. This diagnostic currently uses `curl -k`, which disables TLS certificate
verification.

## Companion repository

`create-rocky9-xrdp-vm.sh` downloads and runs
[`setup-rocky9-xrdp.sh`](https://github.com/hardevsanghera/xrdpOnRocky9/blob/main/setup-rocky9-xrdp.sh)
from the companion
[`xrdpOnRocky9`](https://github.com/hardevsanghera/xrdpOnRocky9.git)
repository. That repository contains the Rocky workstation, XRDP, and VS Code
setup logic. The setup script is fetched from GitHub at VM provisioning time;
it is not cloned onto the VM.
